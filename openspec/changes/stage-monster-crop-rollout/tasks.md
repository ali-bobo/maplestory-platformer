## 1. Batch Plan

- [ ] 1.1 選定 Batch A 的單一來源怪物圖，並記錄該圖會拆出的候選怪物清單。
- [ ] 1.2 為 Batch A 建立輸出命名規則，明確定義圖片檔名、spriteKey、monster id 與目標地圖的對應方式。
- [ ] 1.3 明確列出 Batch B 的承接邊界，包含哪些來源圖、哪些候選怪物與哪些地圖調整暫不納入本批。

## 2. Batch A Monster Onboarding

- [ ] 2.1 只針對 Batch A 來源圖完成裁切或來源對照整理，不處理其他怪物來源圖。
- [ ] 2.2 將 Batch A 怪物分類到單一目標地圖，移除其在其他地圖上的重複出現。
- [ ] 2.3 將 Batch A 怪物接到對應的 runtime asset / monster config / map test roster。
- [ ] 2.4 驗證 Batch A 怪物在指定地圖中可正常生成，且不會同時出現在非目標地圖。

## 3. Guardrails

- [ ] 3.1 若 Batch A 執行中需要新增或修改超過當前批次範圍的怪物，先回寫 design，不直接擴大施工。
- [ ] 3.2 若再次發現問題更像是平台或背景造成，而不是切圖拆分流程，明確記錄為後續批次議題，不與 Batch A 混修。
- [ ] 3.3 每完成一個驗證點就同步更新規格與任務狀態，避免文件與實作再次脫節。
