# 製作人評審：盜賊傳說（整體產品、定位、風險與範圍）

評審日期：2026-10-11。依據：docs 全套、75 筆 git log、src 約 14,200 行、243 個素材檔、test 與 e2e 目錄。本文不重複戰鬥手感、經濟、內容敘事、UX 四份專項評審，只做上層整合。

---

## 1. 結論與定位

**結論**：這個專案目前是「功能堆得很快、但從來沒有人完整玩過一遍」的狀態。TODO.md 自己寫了：三職業、十幾張地圖、星光碎片主線都在，「還沒有人從頭到尾真的玩過」。工程面（資料驅動、純邏輯分離、存檔驗證、約 246 個單元測試、CI 檢查 bundle 同步）遠比一般個人專案紮實，但產品面在橫向擴張：Phase 21 到 23 三個階段加了 2 個職業、5 張地圖、4 種地圖機制，全部都只用「數值換算」驗證過。我的判斷是：**現在應該停止加內容，把已有的東西玩通、調順、做成可分享的 25 分鐘切片。**

**定位一句話**：給想在手機或電腦瀏覽器上花 20 到 30 分鐘玩一段「暗影盜賊奪回星光」的橫向動作 RPG 的朋友與休閒玩家，點開連結即玩，不用安裝、不用註冊。

**真正的鉤子**：不是楓之谷風格（那是別人的風格，且是法律負債），也不是地圖數量。能成為差異的只有三樣：(1) 影子盜賊的「暗影」身份：影分身、背刺、煙幕、毒、印記這組技能詞彙，連同轉職二選一（刺客單點爆發 vs 俠盜近戰群體）；(2) 星光碎片的收集主線（五個守護者、塔點亮的儀式感）；(3) 零安裝的即點即玩，含手機觸控。目前內容並沒有都在服務這三點：台北都會、暗巷城、神秘之境三張支線地圖，以及每日副本，與星光主線沒有關聯，屬於稀釋。

## 3. 垂直切片（Vertical Slice）定義

**目標**：新玩家 25 分鐘內，從開場玩到「第一次轉職」並打贏第一個守護者，有明確收尾畫面。這是第一次分享給朋友的版本。

**切片內容（只含這些）**
1. 標題、教學（縮成 4 頁以內，可全跳過）。
2. 浮空島嶼 → 晨曦鎮 → 森林獵場，Lv1 到 10。
3. Lv10 轉職鏈完整走一次（影之殿堂、二選一、試煉之證、影之試煉、覺醒）。
4. 轉職後再打一張圖（古代廢墟）直到碧濤港守護者「海盜船長」，掉落第 1 塊星光碎片。
5. 回晨曦鎮的星光之塔看到「1/5 亮起」與一張「第一章完」結算卡（可截圖分享，見第 5 節）。
6. 存檔安全、死亡不卡關、手機可完整走完。

**凍結（保留程式碼與資料，但不再投入，也不在切片路徑上暴露）**
- 黃沙遺跡、霜牙峰、熔岩巢穴、魔君王城四張新圖與其機制：已寫完，先上鎖或隱藏傳送門；等切片調順再開。
- 暗影領域最終 Boss 的狂暴視覺。
- 神秘之境、台北都會、暗巷城：整組支線凍結（它們與星光主線無關）。
- 每日副本的獎勵調整；不再新增副本。

**砍掉（不做）**
- 其他職業（戰士、法師、弓箭手）、二轉。
- 後端分數榜（見第 5 節理由）。
- 怪物圖鑑、區域套裝、NPC 好感支線、每日委託的完整版。
- 新的地圖機制、新的 BGM 曲目、純美術物品。
- 水面較滑、可攀船桅這類 ROADMAP 殘項。

**深化（投入在這裡）**
- 轉職後的 3 個專屬技能與普攻的手感差異（交給戰鬥手感評審的結論落實）。
- 守護者戰：現在只是高血量怪，應有一個可辨識的招式與預警（只做海盜船長一隻，做成範本）。
- 任務敘事：把「打 N 隻」中的兩三個改成有對白或選擇的版本。
- 第一個 10 分鐘的節奏與提示（交給 UX 評審）。
- 接上已有的素材：任務標記、idle_2、影之殿堂跳台、飛鏢旋轉。這些是低成本高回報的完成度。

**廣度對深度的建議**：現在是廣度過剩、深度不足。比例應從「新增內容 80%」翻成「調校與完成度 80%」。五張尚未實測的高等級地圖，其風險不在缺內容，而在每張都有未知的平衡與 bug，凍結它們是減少未知數。

## 5. 零後端的分享與成長（依投資報酬率排序）

1. **存檔碼（可複製字串）**：把存檔 JSON 壓縮成 base64url 字串，貼上即還原。解決匯出被擋、跨裝置、朋友間傳角色。成本低，而且是存檔安全網。
2. **結算卡（canvas 畫出，長按或截圖）**：章節完成或死亡時，用 canvas 畫「職業頭像、等級、碎片 n/5、遊玩時間、分數、版本」。無需下載權限，玩家自己截圖。這是最有效的社群傳播素材。
3. **挑戰種子碼**：把「職業 + 等級 + 隨機種子」編成短碼，朋友輸入即同條件開局比分數。需要把掉落與怪物生成的亂數集中成可播種的來源，工程上要先確認現有 Math.random 使用面。
4. **每日挑戰（以日期為種子）**：同一個種子，固定一個限時副本或守護者戰，結果存本機。因為沒有伺服器，不能排行，只能與「朋友貼出的結算卡」比較。
5. **成就與本機紀錄**：10 個左右成就（首次轉職、無傷擊敗守護者、30 分鐘內 Lv10）存 localStorage，並印在結算卡上。便宜、有回訪誘因。
6. **本機排行榜**：只有自己的前 5 名，意義有限，但能加強「再來一次」的心理。

**是否要後端**：現在不要。理由：分數榜需要反作弊（STATUS 自己承認存檔在玩家端無法信任）、帳號或暱稱管理、內容審核與隱私責任，對一個切片尚未驗證的遊戲是過度投資。若日後非要線上榜，使用 Supabase 或 Firebase 的唯讀公開榜加手動審核即可，並且先確認遊戲有人想比。

## 6. 測試與流程建議

**現況**：npm test 約 246 項純邏輯單測（存檔、職業、狀態、音樂、內容交叉檢查）；e2e 目錄有 9 支以上 Playwright 腳本，涵蓋基本流程、轉職任務鏈、技能、手機模擬、世界。CI 跑單測、build、並驗 bundle 同步。**缺口**：e2e 沒進 CI（路徑寫死 /opt/...）；無 soak/效能測試；無平衡回歸；無跨瀏覽器；無真機。

**缺的測試，依價值**
1. **Soak 測試**：Playwright 開 debug，傳送到各圖並循環 10 分鐘（使用 `__game`），每 30 秒記錄 `performance.memory`、場景物件數、監聽器數、FPS；斷言成長低於門檻。最直接保護「瀏覽器崩潰」這個最大技術風險。
2. **平衡回歸測試（純邏輯）**：把怪物 HP、攻擊、玩家傷害公式拉出，寫一個「理想玩家擊殺守護者的秒數與受傷量」的估算測試，設上下界；改數值破界就紅燈。這是把 TODO 裡「只用數值換算」變成保護網。
3. **存檔相容性快照**：把每個版本的存檔樣本放進 test/fixtures，保證舊檔永遠可讀。
4. **Smoke e2e 進 CI**：一支腳本只做開局、走過轉職鏈、存檔重讀，把 Playwright 路徑改成環境變數。
5. **跨瀏覽器**：至少 Firefox 與 WebKit 各跑 smoke 一次（Playwright 支援）。
6. **真機清單**：手動、發布前一次，見第 4 節。

**每次發布的最小測試計畫**：npm test 全綠；build 後 git diff 無差；e2e smoke；soak 5 分鐘；真機手機玩 5 分鐘；版本號與更新紀錄一致。

**CI 建議**：在現有 build.yml 增加 Playwright smoke 工作（快取瀏覽器）；PR 必須通過；另設每週排程跑 soak；npm audit 已有，保留。

**與 AI 助手及平行子代理的作業流程**
- 一個任務一個 worktree 與一個小 PR；PR 描述用固定模板：目的、風險、手動驗證步驟、未做的事。
- **dist/bundle.js 只在合併前於 main 上重建一次**，不要讓多個 PR 各自提交 bundle；否則每個 PR 都會互相衝突。更好的做法：PR 內不含 bundle，合併後由 CI 或一個專門 commit 重建；或乾脆不把 bundle 放進 git，由 CI 部署時建置。
- 並行 agent 的檔案所有權：每個 agent 事先宣告會碰的檔案，大檔（UIScene、Skill、BaseMapScene）同時只允許一個 agent 修改。
- 決策寫進 `docs/DECISIONS.md`（一行一條，日期、決定、理由、被否決的選項），取代散落在 STATUS 與 TODO 的口頭決定。
- 文件瘦身：STATUS 改成只寫現況與已知問題，歷史搬到 CHANGELOG；GAME_SPEC、ASSET_REQUEST、JOB_PROMPTS 標為歸檔。防止「文件與程式不符」。
- 防回歸：每修一個 bug 加一個測試；每新增地圖必須先通過 content.test；大檔拆分（UIScene 先拆）放在凍結內容期間做。
- 對 AI 助手的規則：不允許「順手」擴張範圍；每個 session 開頭先讀 DECISIONS 與本評審的切片定義。

## 7. 前十名行動排序

排序依據：玩家價值、風險降低、投入成本。

1. **自己完整玩一遍切片路徑並記錄數據**（零成本，最高資訊價值，是所有調校的前提）。
2. **移除 hisoka.jpg 並清歷史；去除 Maple 命名；確認 AI 素材授權**（不做就不能公開）。
3. **凍結四張新圖與三張支線圖，鎖定切片範圍**（減少未知）。
4. **存檔碼（複製字串）+ 存檔安全**（保護玩家進度，也是分享基礎）。
5. **真機手機驗證**（受眾包含手機，卻從未實測）。
6. **soak/記憶體測試 + 並行中的洩漏修復驗收**（崩潰會殺死口碑）。
7. **海盜船長守護者戰做成範本（預警、招式、手感）+ 轉職後技能手感**。
8. **結算卡（canvas 截圖卡）與版本號、回饋入口**。
9. **接上已有素材（任務標記、idle_2、跳台、飛鏢旋轉）並替換暫代技能圖示**。
10. **公開可存取的靜態託管（取代私人 Artifact）+ CI 加 smoke e2e**。

**不做的事**：世界地圖傳送（階段 3，等切片驗證後再說）、後端分數榜、新職業、新地圖、新 BGM、Boss 狂暴視覺。

**六個 Session 路線圖**

| Session | 主題 | 完成定義 |
